## 一、总体结论

**架构是专业级的，产出是事故级的。**

设计思路（句法结构算子 + 保义校验 + 迭代选优 + 重合度闭环）明显高于市面"同义词替换"类工具，但这个思路的正确性还没有转化为可交付的产品能力。当前版本更接近"能跑通的技术验证"，不是"能交给用户的结果"。

## 三、四个致命问题（附实证）

### 3.1 拆分算子的"保义度后门"制造病句

`rewriter/pipeline.py:180`

```python
# 拆分是算法无损变换 (token 全保留), 解析差异大属正常, 放宽门槛
min_fid_eff = min(min_fid, 0.45) if 'split' in used else min_fid
```

只要候选用了 `split`，保义度门槛就从 0.65 降到 **0.45**。这让语义崩坏的候选直接过闸。

**实证**（保义度 0.5966，本该被丢弃，因用了 split 被放行）：

```
原：真理的客观性指真理的内容是对客观事物及其规律的正确反映
新：真理的客观性指正确反映，它真理的内容是对客观事物及其规律。
```

主语、宾语、谓语全部错位，已不构成可读句子。

另一例（保义度恰好 0.65 卡线通过）：

```
原：真理的客观性决定了真理的一元性。
新：客观性决定了真理的一元性，它是真理的。
```

"它是真理的。"——句子被砍断，宾语丢失。

### 3.2 拆分点选在谓宾动词之后

`rewriter/operators/split.py:15-17` 的 `_LEAD_OK` 白名单包含"由此""从而"等词，且拆分规则只判断"右侧是否有谓语"，不判断"左侧谓语是否还缺宾语"。

**实证**：

```
原：真理的客观性表明，要想发现真理、拥有真理……只能采取老老实实的科学态度
新：真理的客观性表明。要想发现真理、拥有真理……只能采取。
```

"表明"是谓宾动词，后面必须带宾语从句。在这里断句，等于把句子拦腰砍断。同类动词还有：表明、说明、指出、认为、强调、证明、意味着。

历史输出中 `由此揭示句子的结构。`（缺主语）也是同一根因。

### 3.3 通顺度打分只查标点，不查语法

`rewriter/scorer.py:34-70` 的 `fluency_of()` 只检查三件事：句长比、标点配对、连接词重复。

**它不检查语法是否成立。** 上述三个病句在它眼里全是满分：

- "真理的客观性表明。" → 有句号、长度合适、无重复连接词 → 1.0
- "客观性决定了真理的一元性，它是真理的。" → 同上 → 1.0

这是整个质检环节最薄弱的空档：**没有语言模型参与判断，通顺度就是格式检查。**

### 3.4 优化目标与真实查重不对齐

`rewriter/pipeline.py:75-81`

```python
corpus = overlap.load_corpus(corpus_dir)
# 原文自身也是比对源 (novelty 对照)
corpus += [s for s in split_text_to_sentences(text) if s.strip()]
```

把**原文自己**加入比对语料，带来两个后果：

1. 每一句都能与自己在语料中完全匹配 → `cur_run` 恒等于句长 → 必然超过阈值 10 → **每一句都被判定为"需要改"**，包括用户完全原创的句子。
2. `novelty_of()` 衡量的是"离原文有多远"，不是"离查重库有多远"。外部语料仅 12 句，几乎不命中，指标退化为"改动幅度"。

**这意味着系统在优化一个错误的目标**：它奖励"改得多"，而不是奖励"与真实文献不重合"。

## 四、改进清单

按投入产出排序。P0 为"不改就是负产品"，P1 为"决定能否商用"，P2 为"规模化前提"。

### P0 · 止血（1–2 天）

| # | 改进              | 位置                      | 做法                                                           | 预期           |
| - | --------------- | ----------------------- | ------------------------------------------------------------ | ------------ |
| 1 | 取消 split 的保义度后门 | `pipeline.py:180`       | 删除 `min(..., 0.45)` 分支；改为对每个子句单独做保义校验                        | 病句率直接砍半      |
| 2 | 禁止在谓宾动词后断句      | `operators/split.py`    | 拆分点校验：若左半末词为「表明/说明/指出/认为/强调/证明/意味着/发现」，或该词依存树上有被切走的宾语 → 拒绝拆分 | 消除"……表明。"类硬伤 |
| 3 | 拆分后子句完整性校验      | `operators/split.py` 新增 | 每个子句必须能解析出「主语 + 谓语」；右半以"由此/从而/因此"开头时强制要求有主语                  | 消除缺主语病句      |
| 4 | fluency 接语言模型   | `scorer.py`             | 接入 KenLM 中文 5-gram（约 100MB，毫秒级）算困惑度；或用小型中文 GPT 打分            | 病句不再满分       |

> 做完 P0，病句率预期从 60% 降到 10% 以内。这是"能不能给人看"的分水岭。

### P1 · 有效性（3–5 天）

| # | 改进                | 位置                                                                         | 说明                                                                                                       |
| - | ----------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 5 | **开启 LLM 整句重写算子** | `config.yaml` → `generative.enabled: true`；`operators/generative.py` 已留好接口 | 当前 6 个规则算子在真实长句上覆盖率仅 31%，这是能力天花板的根本原因。规则算子做微调，LLM 做整句重写，现有 verifier 做保义兜底。成本约 0.001 元/句，一篇 500 句 ≈ 0.5 元 |
| 6 | 原文退出比对语料          | `pipeline.py:79-80`                                                        | 改为"只与外部语料比对"。若用户提供查重报告（知网/维普标红段落），则只改标红部分；无报告时降级为"表达润色"模式，不宣称降重                                          |
| 7 | 超阈指标改为字符占比        | `overlap.py` `report()`                                                    | 拆句会让 1 句变 2 句，"超阈句数"会虚高（实测 14→15 恶化，但平均重合其实降了 30%）。应改为"超阈字符数 / 总字数"                                      |
| 8 | 纯规则算子再补 3 个       | `operators/`                                                               | 建议补：`nominalization`（动词名词化互转）、`clause-embed`（定语从句↔分句）、`paraphrase-frame`（"通过X实现Y"↔"Y的实现依赖X"）             |

### P2 · 规模化前提（1–2 周）

| #  | 改进                   | 说明                                                                                                                |
| -- | -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 9  | **比对算法换索引**          | `overlap.py:18-43` 是 O(len(a)×len(b)) 的 DP，且对每句遍历全语料。语料 12 句时没事，扩到 10 万句直接跑不完。必须换 n-gram 倒排索引 / SimHash 预筛 + 局部精算 |
| 10 | 硬换行预处理               | 实测暴露：PDF/Word 复制文本被硬换行切成半句（"真理中包含着不依赖于人" / "和人的意识的客观内容。"），工具当成两句处理，全盘错位。规则：行尾无终止标点且下一行非标题/编号 → 合并                 |
| 11 | docx 直读 + 原格式回写      | 学生交付物是 Word，必须保留字体、行距、编号、脚注                                                                                       |
| 12 | 字数上限 2 万→10 万 + 异步队列 | `web/app.py:MAX_TEXT_CHARS`；同步请求等 5 分钟必超时                                                                         |
